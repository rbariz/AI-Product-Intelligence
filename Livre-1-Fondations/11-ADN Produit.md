# Question fondamentale

**Comment identifier automatiquement les caractéristiques fondamentales d'un produit afin de guider toutes les décisions futures ?**

---

# Pourquoi cette question est importante

Deux produits peuvent résoudre le même problème métier.

Pourtant, ils nécessitent parfois des architectures totalement différentes.

La raison est simple :

Ils ne possèdent pas le même ADN.

L'objectif de la plateforme est donc de découvrir cet ADN avant toute recommandation importante.

---

# Notre conviction

L'ADN Produit représente l'identité structurelle d'un produit.

Il ne décrit pas les fonctionnalités.

Il décrit les caractéristiques profondes qui influenceront durablement :

- l'architecture ;
- la sécurité ;
- la scalabilité ;
- les performances ;
- les technologies ;
- les risques.

L'ADN constitue le profil stratégique du produit.

---

# Définition

L'ADN Produit est un ensemble de caractéristiques calculées à partir du Product Knowledge Model.

Il ne résulte pas d'une déclaration de l'utilisateur.

Il est déduit par le moteur de raisonnement.

---

## Modèle économique

Exemples :

- Marketplace
- Plateforme
- Produit interne
- Application métier
- Produit grand public

Le produit est-il :

- B2B
- B2C
- B2B2C
- Interne
- Multi-organisations

---

## Complexité métier

Le moteur estime notamment :

- nombre de capacités métier ;
- richesse des règles ;
- nombre de processus ;
- dépendances.

---

## Temps réel

Le produit nécessite-t-il :

- des mises à jour instantanées ;
- des notifications ;
- des flux continus ;
- des événements.

---

## Intelligence Artificielle

L'IA est-elle :

- absente ;
- complémentaire ;
- importante ;

- des données personnelles ;

## Évolutivité

- variabilité métier.

---

# Calcul de l'ADN

L'ADN n'est jamais saisi.

Il est calculé à partir :

- des concepts ;
- des relations ;
- des règles ;
- des contraintes ;
- des hypothèses validées ;
- des décisions prises.

Le calcul est réévalué après chaque enrichissement du Product Knowledge Model.

---

# Pourquoi l'ADN est important

L'ADN influence directement :

- les patterns d'architecture ;
- les choix techniques ;
- les priorités de sécurité ;
- les mécanismes de montée en charge ;
- les recommandations d'infrastructure.

Une architecture devient alors la conséquence naturelle de l'ADN du produit.

---

# Explicabilité

Chaque caractéristique de l'ADN doit pouvoir être expliquée.

Exemple :

Temps réel : Oui

Justification :

- notifications instantanées ;
- suivi des opérations en direct ;
- synchronisation multi-utilisateurs.

Le moteur doit toujours justifier son analyse.

---

# Évolution

L'ADN n'est pas figé.

Il évolue lorsque le produit évolue.

Une nouvelle capacité métier peut modifier plusieurs dimensions de l'ADN.

Le moteur conserve l'historique de ces évolutions.

---

# Décisions prises

- L'ADN Produit est calculé, jamais déclaré.
- Il représente l'identité structurelle du produit.
- Il guide les recommandations d'architecture.
- Il est entièrement explicable.
- Il évolue avec le Product Knowledge Model.
